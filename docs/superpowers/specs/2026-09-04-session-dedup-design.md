# Дизайн: дедупликация треков в сессии («перемешать» «Мою волну»)

Дата: 2026-09-04
Статус: согласован с пользователем

## Контекст и проблема

`yam` — терминальный плеер радиостанций Яндекс Музыки. Станция «Моя волна»
(`user:onyourwave`) — это **лента рекомендаций, которую формирует сервер**:
`client.stationTracks()` (yam.go) возвращает пачку (`batch`) треков, плеер
играет их строго по порядку (`wave.take()`, `wave.next()`), и когда пачка
исчерпана — запрашивает следующую (seed = последний проигранный трек).

Пользователь жалуется, что «попадаются треки, которые недавно буквально
встречались» — точные повторы. Причине способствует то, что порядок решает
сервер, а клиент не помнит, что уже играл.

Важное ограничение: дедуп уберёт только **ровно повторяющиеся** треки.
*Схожие* треки, которые сервер реально рекомендует по профилю, останутся —
это поведение самой станции, а не баг клиента.

## Цель

Не повторять в рамках одной сессии треки, которые уже прозвучали. Повторы
пропускать молча (без фидбека в API). Если пачка целиком состоит из повторов —
запрашивать новую. Чтобы длинная сессия не «убивала» радио, помнить не всю
сессию, а **окно в последние N треков** (скользящее).

## Сcope (границы)

Входит:
- Дедуп по скользящему окну в N последних треков сессии.
- Тихий пропуск повторов и «пустых» элементов (реклама, `Track == nil`).
- Перезапрос новой пачки при исчерпании текущей.
- Настройка размера окна через переменную окружения.

Не входит (YAGNI, отдельными шагами при желании):
- Случайный порядок треков (true shuffle) — сервер и так упорядочивает ленту.
- Дедуп между запусками (персистентная история).
- Прочие действия: повтор трека, превью очереди, громкость, отчёт и т.п.

## Детали реализации (только `yam.go`, структура `wave`)

### 1. Скользящее окно последних треков

В `wave` добавляем:
- `recentSeq []string` — порядок добавления (для эвикции старейшего).
- `recentSet map[string]bool` — O(1) проверка «уже в окне».
- `window int` — размер окна.

`markRecent(id string)`:
- если `id` уже в `recentSet` — ничего (идемпотентно).
- иначе: добавляем в `recentSet` и в конец `recentSeq`.
- если `len(recentSeq) > window` — снимаем старейший (`recentSeq[0]`) из
  обоих структур.

Ключ — `track.trackID()` (формат `id:albumId`), чтобы различать треки,
доступные в нескольких альбомах.

### 2. Размер окна

- Переменная окружения `YAM_DEDUP_WINDOW`, целое, по умолчанию **100**,
  минимум 1. Неверное/отсутствующее значение → дефолт 100.
- Читается при создании `wave` (`newWave`).

### 3. `take()` — курсорная логика с дедупом

Переписываем `wave.take()` так, чтобы он сам двигал курсор и находил
уникальный трек:

```
refetches := 0
for {
    if w.index >= len(w.batch.Sequence) {
        if refetches >= maxBatchRefetches {   // защита от зацикливания
            return w.takeAnyway()
        }
        seed := ""
        if w.cur != nil { seed = w.cur.trackID() }
        if err := w.refetchBatch(seed); err != nil { return nil, err }
        refetches++
        continue
    }
    seq := w.batch.Sequence[w.index]
    w.index++
    if seq.Track == nil { continue }                    // «реклама»/пусто
    if w.recentSet[seq.Track.trackID()] { continue }    // уже в окне → тихо
    w.cur = seq.Track
    w.markRecent(w.cur.trackID())
    w.c.feedback(w.station, "trackStarted", w.batch.BatchID, w.cur.trackID(), "", 0)
    return w.cur, nil
}
```

Повтор и пустые элементы пропускаются **молча** — без `trackStarted` и любого
фидбека в API.

### 4. `refetchBatch(seed string)`

Выносим текущую логику перезапроса (из `next()`) в отдельный метод:
- `client.stationTracks(w.station, seed)`.
- Если последовательность пуста — ошибка.
- Записываем `w.batch`, шлём фидбек `radioStarted`, `w.index = 0`.

### 5. `start()` и `next()`

- `start()`: получает первую пачку (`stationTracks(station, "")`), шлёт
  `radioStarted`, `w.index = 0`, затем `return w.take()`.
- `next(playedFull, played)`: по завершённому `w.cur` шлёт `trackFinished`
  (если дослушан) или `skip` (если пропущен) — **как сейчас**; затем
  `return w.take()`.

Курсор `w.index` теперь — «следующий непробегнутый слот»; `take()` всегда
продвигается вперёд, поэтому `next()` не обязан сам двигать индекс.

### 6. Защита от зацикливания — `takeAnyway()`

`maxBatchRefetches = 3`. Если 3 раза подряд новая пачка целиком из повторов/
пустых — играем первый доступный реальный трек **даже если он повтор**,
выводим предупреждение в терминал:
`  [warn] доступные треки уже прозвучали, играю <название>` — и шлём
`trackStarted`. Радио не останавливается. Если реального трека нет — ошибка.

## Поведение и сценарии

- Обычный случай: следующий трек новый → играет, как раньше.
- Следующий = повтор в окне → молча берём следующий в пачке.
- Пачка доиграна → запрашиваем новую (seed = последний трек).
- Вся пачка повторы → новая; 3 раза подряд → играем первый доступный + warn.
- «Реклама»/пустой слот → молча пропускаем (было так и раньше, но раньше это
  было ошибкой; теперь — норма).

## Тестирование / верификация

- `go build -o yam .` и `go vet ./...` — компиляция и стат. анализ.
- `./yam --check` — smoke-тест (токен → трек станции → ссылка на стрим).
- Ручная проверка: запустить плеер, прослушать несколько треков, убедиться,
  что недавние повторы не повторяются; при исчерпании — новая пачка.
- (Опционально, если появится тест-харнесс) юнит-тест курсорной логики
  `take()` на синтетической `batch` с повторами.

## Риски

- Сервер может считать пропущенные треки «не услышанными» — но мы не шлём по
  ним фидбек, поэтому рекомендации не искажаются лишними `skip`.
- На очень длинной сессии окно в 100 может не покрыть «давно проигранные»
  треки; при желании окно расширяется через `YAM_DEDUP_WINDOW`.
